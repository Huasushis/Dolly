# ADR 0008: Pin MCP 2025-06-18 until multi-round-trip effects have a durable ledger

- Status: Accepted
- Scope: Host Tool Broker MCP adapter
- Compatibility: freezes the only MCP revision accepted by
  `dolly.tool-broker-config/v1`
- Affected requirements: `REQ-TOOL-001`, `REQ-TOOL-002`, `REQ-TOOL-008`

## Context

The planning baseline recommends the official Rust MCP SDK and refers to the
current MCP specification. The repository originally fixed `2025-06-18` but
did not explain why that older revision was normative.

MCP `2026-07-28` is not wire-equivalent. It removes protocol sessions and the
`initialize`/`notifications/initialized` lifecycle, moves version and client
capabilities into every request, and allows `tools/call` to return
`input_required`. Continuing such a call requires a new JSON-RPC request ID,
the original arguments, exact opaque `requestState`, and possibly brokered
elicitation, sampling, or roots responses.

Dolly v1 deliberately records one dispatch boundary and forbids automatic
redispatch after `DISPATCHED` for every side-effect class. It has no durable
per-round Tool state, capability/consent broker for MCP client requests, or
crash rule that can prove whether a continuation is a transport retry or a new
external effect. Silently selecting the newer protocol would therefore create
two incompatible conforming implementations.

## Decision

`dolly.tool-broker-config/v1` accepts exactly MCP `2025-06-18`. Candidate
prepare performs and verifies that revision's initialize/initialized lifecycle
and rejects version fall-forward. The adapter validates only that revision's
message shapes. A `2026-07-28` discovery, stateless metadata contract, or
`input_required` result is version-foreign and never authorizes another
`tools/call`; any operation disposition still respects the already crossed or
uncrossed durable dispatch boundary.

The reference implementation may use a current official Rust SDK only if the
locked build passes the SDK's legacy `2025-06-18` conformance path and cannot
silently select a newer lifecycle. SDK compatibility is implementation
evidence, not permission to change the configured protocol.

## Upgrade gate

A future MCP revision requires a new Tool Broker schema/adapter version and an
ADR defining at least:

- one durable identity and outbound digest for every MRTR round;
- the relationship between the Dolly operation ID, changing JSON-RPC IDs,
  original arguments, `inputResponses`, and opaque `requestState`;
- the exact dispatch boundary and unknown-outcome rule for each round;
- capability, authorization, consent, redaction, and quota rules for every
  elicitation, sampling, or roots request;
- maximum rounds, bytes, wall/monotonic deadlines, cancellation, and loop
  disposition;
- crash recovery and whether a continuation can ever be safely reconstructed;
  and
- migration/coexistence rules for retained registry revisions and generations.

The upgrade must include official per-version conformance results plus Dolly
failure-injection vectors. An SDK version bump alone does not pass this gate.

## Alternatives rejected

- Treat `protocol_version` as a preferred minimum: allows silent semantic
  changes and makes retained calls dependent on server negotiation.
- Adopt `2026-07-28` but reject only `input_required`: claims a protocol while
  violating its client requirements and still leaves lifecycle differences.
- Map every MRTR continuation to the original dispatch: erases independent
  request/effect boundaries.
- Map every continuation to a fresh Dolly operation automatically: bypasses
  Module authorization and the no-post-dispatch-replay rule.

## Consequences and rollback

Some current MCP-only servers will require a compatibility mode or will be
unavailable in Dolly v1. This cost is explicit and testable. Rollback from an
attempted future adapter leaves the v1 adapter and retained `2025-06-18`
registry revisions unchanged; it does not reinterpret existing ledger rows.

`TST-TOOL-008` verifies that a candidate configured for `2026-07-28` is
rejected before activation and cannot alter the active registry or start a Tool
server generation.
